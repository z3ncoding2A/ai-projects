# Hyper Commander

## Project Overview
Hyper Commander is an AI-powered, voice-controlled desktop assistant tailored for an Arch Linux system running the Hyprland window manager. It listens for specific wake words (e.g., "Hey Hyper") using a local `faster-whisper` model. Once activated, it records the user's voice command, transcribes it, and sends the transcription to Google's Gemini LLM. Gemini is instructed to translate the natural language command into executable bash or `hyprctl` commands, which are then executed directly on the host system to control applications, window states, and system settings.

### Main Technologies
*   **Python:** Core programming language.
*   **faster-whisper:** Local speech-to-text for efficient wake-word detection and command transcription.
*   **sounddevice & numpy:** Audio recording and processing.
*   **google-genai:** Interfacing with Google's Gemini models for command interpretation and translation.
*   **Hyprland (`hyprctl`) & Bash:** Target environments for command execution.

## Building and Running

1.  **Setup Environment:**
    Run the provided setup script to automatically create a Python virtual environment and install all necessary dependencies defined in `requirements.txt`.
    ```bash
    ./setup.sh
    ```

2.  **Configuration:**
    Ensure you have your Gemini API key set as an environment variable before running the application.
    ```bash
    export GEMINI_API_KEY='your_api_key_here'
    ```

3.  **Run Application Daemon:**
    Activate the virtual environment and start the daemon.
    ```bash
    source venv/bin/activate
    python main.py daemon
    ```

4.  **Execute Commands (Hotkey):**
    Bind the following command to a keyboard shortcut in your Hyprland config (e.g., `bind = SUPER_ALT, D, exec, /path/to/venv/bin/python /path/to/main.py toggle`) to start and stop recording your voice.
    ```bash
    python main.py toggle
    ```

## Development Conventions & Architecture
*   **System Environment Constraints:** The application (and supporting AI prompts like `system-helper.md`) is heavily tailored towards a specific Arch Linux environment with exact hardware specs (Intel Core i5-14400F, NVIDIA RTX 5060, Zen kernel). Development should align with this hardware baseline.
*   **LLM Interactions:** The system instruction given to Gemini strictly enforces returning *only* raw executable shell commands without markdown blocks or conversational filler. If a command is purely conversational, it is prefixed with a `#`.
*   **Safety & Execution:** Commands generated by the LLM are directly executed via `subprocess.Popen(..., shell=True)`. Extra care should be taken regarding destructive commands. `system-helper.md` outlines strict "Do No Harm" guardrails and requires rollback/backup commands for critical system modifications.
*   **Automation-Ready Output:** The LLM is instructed to use dynamic bash syntax and environment variables (e.g., `$(whoami)`) instead of static placeholders to ensure commands run successfully out-of-the-box via piping.
