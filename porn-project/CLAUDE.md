## Architecture

This project follows a 3-layer architecture (see AGENTS.md for full detail):

1. **Directive Layer** — SOPs in Markdown files (`directives/`, `plans/`). Living documents; update them when you discover API constraints, better approaches, or edge cases.
2. **Orchestration Layer** — You (the AI). Read directives, route to execution scripts, handle errors, and self-anneal (fix → test → update directive).
3. **Execution Layer** — Deterministic Python scripts. Do not manually replicate what a script already does; check `scratch/` and the project root first.

**Before writing new code**, check if an existing script covers the task.

## Running the Project

```bash
# Use .venv Python, not system Python 3.14
source .venv/bin/activate   # or prefix commands with .venv/bin/python

# Generate/refresh the video grid HTML (scrapes profile, downloads thumbnails)
python generate_grid.py

# Serve the grid locally at http://localhost:8888 (auto-opens Chrome)
python serve.py

# Test yt-dlp format extraction
python test_api.py

# Test HLS proxy logic
python test_proxy.py

# React frontend (work-in-progress redesign, in frontend/)
cd frontend && npm run dev    # dev server (Vite HMR)
cd frontend && npm run build  # production build to frontend/dist/
cd frontend && npm run lint   # oxlint
```

## Key Files

| File | Purpose |
|---|---|
| `generate_grid.py` | Scrapes Pornhub profile, downloads thumbnails to `thumbs/`, generates `z3ncoding_videos_grid.html` |
| `serve.py` | HTTP server (port 8888); exposes `/api/streams` (yt-dlp formats) and `/api/proxy` (CORS HLS proxy) |
| `z3ncoding_videos_grid.template.html` | Source template for the interactive UI — edit this, not the generated HTML |
| `categories.json` | Persists user video categories (public / least / average / most / pending / explode) |
| `blacklist.txt` | Viewkeys excluded from the grid |
| `manual_videos.json` | Manually added video entries |

## Data Flow

```
Pornhub profile → generate_grid.py → z3ncoding_videos_grid.html
                        ↓
                  thumbs/ (local thumbnail cache)

serve.py → /api/streams  (yt-dlp extracts video formats)
         → /api/proxy    (proxies m3u8 / MP4 for CORS)
```

## Frontend (React, `frontend/`)

A work-in-progress React+Vite redesign (see `plans/ui_redesign.md` for the "Cinematic Dark" spec). It is separate from the legacy HTML template and not yet wired into the Python server. Stack: React 19, Zustand (state), TanStack Virtual (virtualised grid), Framer Motion, Chart.js.

```
frontend/src/
  App.jsx        — root component
  components/    — UI components
  hooks/         — custom React hooks
  stores/        — Zustand stores
  utils/         — shared helpers
```

The frontend talks to `serve.py` on port 8888 for `/api/*` endpoints (same CORS headers are already set).

## serve.py API

| Endpoint | Method | Purpose |
|---|---|---|
| `/api/streams?url=<url>` | GET | yt-dlp format extraction |
| `/api/proxy?url=<url>` | GET | CORS proxy for m3u8/MP4 |
| `/api/<resource>` | GET | Read JSON/text data files |
| `/api/<resource>` | POST | Write JSON/text data files |

Resources: `categories`, `blacklist`, `videos`, `playlists`, `tags`, `history`.

## Development Notes

- **Python environment:** Use `.venv` (Python 3.11). System Python is 3.14 and breaks ML/scraping deps.
- **Template vs generated:** The UI lives in `z3ncoding_videos_grid.template.html`. `z3ncoding_videos_grid.html` is regenerated by `generate_grid.py` and should not be hand-edited.
- **Thumbnail caching:** `thumbs/` is ~400MB of cached images. Scraper checks local cache before fetching.
- **Pagination:** Scraper supports up to 100 pages; rate-limited at 1.5s between pages.
- **Category persistence:** Categories are stored in both `categories.json` (server-side) and `localStorage` (client-side); the HTML UI exports/imports between them.
- **Utility scripts** in `scratch/` are for bulk data manipulation (category edits, template regeneration); run them directly as needed.
