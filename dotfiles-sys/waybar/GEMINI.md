# GEMINI Context: Waybar Configuration (HyDE / Hyprdots / Hyprwhspr)

This directory houses a highly customized, modular, and dynamic **Waybar** status bar configuration designed for Hyprland/Wayland, optimized for the **HyDE** (formerly Hyprdots) environment, and integrated with the **Hyprwhspr** custom tray.

---

## Directory Overview

This setup decouples layout, styling, variables, and external modules into separate configuration files to enable dynamic themes (such as Wallbash colors) and autogenerated synchronization (e.g., matching border-radius with Hyprland).

### Core Features
- **Pill-Based Layout**: Modules are clustered into logical "pills" on the left, center, and right.
- **Dynamic Styling**: Style files are automatically watched and reloaded on change (`reload_style_on_change: true`).
- **Autogenerated Styles**: Border radii (`border-radius.css`) and global font definitions (`global.css`) are programmatically updated by HyDE to match system state.
- **Theme Coupling**: Colors are managed cleanly in `theme.css`, allowing external tooling/scripts to easily inject themes without mutating main stylesheets.

### Detailed Component Summary

#### 1. Configuration & Layouts
*   **`config.jsonc`**: Defines the layout order. It maps widgets into several pill groups (e.g., `group/pill#left1`, `group/pill#right1`, etc.). Sourced standard modules from `$XDG_CONFIG_HOME/waybar/modules/*` and local includes.
*   **`custom/gpu_vram`**: (In `config.jsonc`) A custom inline module querying active NVIDIA VRAM usage (`nvidia-smi`) and returning percentage, used, and total memory values formatted as JSON for Waybar.
*   **`hyprwhspr-module.jsonc`**: A dedicated custom module config (`custom/hyprwhspr`) executing `/usr/lib/hyprwhspr/config/hyprland/hyprwhspr-tray.sh` for status monitoring, clicking to record, and right-clicking to restart.
*   **`includes/includes.json`**: Centralizes external JSON modules loaded into Waybar from `/home/z3ncoding123/.local/share/waybar/modules/`. It also overrides widget positions and scales (e.g., `tray`, `wlr/taskbar`, `image#wallpaper`).

#### 2. Styling System (`*.css`)
*   **`style.css`**: **DO NOT EDIT THIS FILE DIRECTLY.** It imports external shared styles (e.g., Hyprwhspr base stylesheet, local share `hyprdots.css`), theme colors, and custom overrides.
*   **`theme.css`**: Defines CSS color variables (e.g., `@define-color bar-bg`, `main-bg`, `main-fg`, `wb-act-bg`). These variables are modified by HyDE/Hyprdots theme switches.
*   **`user-style.css`**: **SAFE FOR USER EDITS.** Sourced last in `style.css`, so any selectors defined here will cleanly override default/theme behaviors.
*   **`includes/border-radius.css`**: **DO NOT EDIT.** This file is autogenerated by HyDE to dynamically match the border-radius of active Hyprland windows. It parses and applies a pseudo-unit `pt` to avoid rendering issues.
*   **`includes/global.css`**: Configures base resets, font family (`JetBrainsMono Nerd Font`), and font size, dynamically updated by HyDE base theme settings.

## Development & Customization Guidelines

Follow these guidelines to ensure edits are clean, safe, and do not break the dynamic update loop managed by HyDE/Hyprdots:

### 1. Customizing Styles & Theme
*   To add custom styling rules, **always edit `user-style.css`**. Never touch `style.css` or files in `includes/` directly as they are prone to being overwritten or break imports.
*   To inspect or modify colors, reference the active GTK or theme-specific variables defined in `theme.css`.

### 2. Modifying Modules or Positioning
*   Modules are specified in `config.jsonc`.
*   If you need to include or exclude specific standard modules, verify if they are defined in `includes/includes.json`. This file acts as a router pointing to actual JSON files located in `~/.local/share/waybar/modules/`.
*   Positions and alignments are customized via standard Waybar JSON configurations in `config.jsonc`.

### 3. Backups and Rollbacks
*   The `layouts/backup/` directory contains copies of working layouts timestamped with pattern `{id}_{date}_{time}.jsonc`.
*   If a structural modification fails or breaks parsing, inspect or restore configurations from `layouts/backup/`.

### 4. Running & Validating Changes
*   Since `reload_style_on_change` is enabled in `config.jsonc`, Waybar will automatically apply style edits as soon as CSS files are saved.
*   To manually restart Waybar or apply hard config changes, run:
    ```bash
    killall waybar && waybar &
    ```
    *(Or trigger the standard HyDE waybar reload keybind or toggle script if active).*
